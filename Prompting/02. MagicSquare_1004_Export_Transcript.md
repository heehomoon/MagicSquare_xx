## Mom Test 워크북 — 각 항목 의미

| 항목 | 쓰는 내용 |
|---|---|
| **페르소나** | 인터뷰한 **한 사람**의 구체적 프로필 (역할, 상황, 빈도) |
| **인터뷰 답변 (과거 사실)** | “~하면 좋겠다”가 아니라 **실제로 한 일·겪은 일**만 인용 |
| **표면 문제 (금지)** | 솔루션이 섞인 문장 — “~앱/기능이 있으면…” 같은 가설 |
| **진짜 문제 (한 문장)** | **행동·감정·비용**으로만 쓴, 솔루션 없는 문제 정의 |

## 작성 가이드

### 1. 페르소나
Mom Test에서는 “타깃 전체”가 아니라 **실제 인터뷰한 1명**을 적습니다.

**좋은 예:**
> 32세, 스타트업 1인 마케터. 주 3회 콘텐츠 기획·배포. 팀원 2명, 예산 없음. MagicSquare 후보 사용자.

**나쁜 예:**
> “20~40대 직장인” (너무 넓음)

---

### 2. 인터뷰 답변 (과거 사실)
Mom Test 3원칙 중 **“미래 가정 말고 과거 구체적 사실”**에 해당합니다.

**좋은 예 (과거·구체):**
- “지난달 캠페인 3번, 엑셀+노션+슬랙을 오가며 정리했다.”
- “어제도 2시간 넘게 수동으로 데이터 맞춤.”
- “비슷한 도구 2개 써봤는데, 2주 만에 그만뒀다.”

**나쁜 예 (미래·가정):**
- “자동화되면 쓸 것 같다.”
- “MagicSquare 있으면 좋을 것 같다.”

---

### 3. 표면 문제 (금지 — 솔루션 섞인 문장)
**의도적으로 “틀린” 문장**을 적어, 솔루션이 섞이면 어떻게 왜곡되는지 보는 칸입니다. 실제 문제 정의로 쓰면 안 됩니다.

**표면 문제 예 (솔루션 포함 → 금지):**
- “데이터를 한 곳에 모아주는 **대시보드**가 필요하다.”
- “**AI가** 콘텐츠 초안을 써주면 좋겠다.”
- “**MagicSquare** 같은 **통합 도구**가 있으면 편할 것 같다.”

공통점: **제품·기능·방법**이 문장 안에 들어감.

---

### 4. 진짜 문제 (한 문장)
표면 문제에서 **솔루션·기능명을 전부 빼고**, 인터뷰 사실만으로 한 문장으로 압축합니다.

**진짜 문제 예:**
> “캠페인마다 여러 도구에 흩어진 정보를 수동으로 맞추느라, 배포 전날마다 2시간 이상 불안하게 반복 확인한다.”

체크리스트:
- [ ] 제품/기능 이름 없음  
- [ ] “~하면 좋겠다” 없음  
- [ ] **언제·얼마나·어떤 감정/비용**이 드러남  
- [ ] 인터뷰 **과거 사실**에서만 도출됨
